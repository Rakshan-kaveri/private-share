# Architecture and trust boundaries

Google Identity Services supplies an ID credential; the Spring backend validates it against the configured OAuth client ID and issues a one-hour in-memory bearer session. The browser authenticates its WebSocket on the first message. The server determines the sender from the authenticated socket, not a client `from` field, and restricts messages to the two parties in a registered session. A second sign-in from the same account replaces the old socket. Disconnect closes its active sessions.

For a file transfer, the sender invites an online peer, both browsers sign ephemeral ECDH public keys with their persistent browser-local ECDSA identity, and each pins the other's first observed identity key. ECDH/HKDF derives a per-transfer AES-GCM key. Chunks use a fresh random 64-bit prefix plus a monotonically increasing 32-bit index as the 96-bit nonce, with transfer ID, index and total as additional authenticated data. The sender signs a final SHA-256 manifest. The receiver checks signatures, chunk authentication, size and digest before downloading. The application server never receives file contents; a TURN server can relay encrypted packets.

For media, the caller captures tracks after a user action, invites a recipient, and the recipient explicitly accepts before capture for voice and video calls. A dedicated screen session can be viewed without requesting the receiver’s microphone. Each peer signs the invite/accept metadata and SDP with its local ECDSA key; the other checks the signature and pinned key. SDP integrity binds the DTLS fingerprint conveyed in the SDP to the pinned key. The signalling service routes offers, answers and ICE candidates between the two authenticated participants. The existing RTCPeerConnection carries audio/video with DTLS-SRTP. Additional screen tracks are added and renegotiated on that connection. Capture stops on hangup or native browser stop. Screen content and microphone/camera samples do not traverse the Spring application.

This is browser-local TOFU, not an independently authenticated account-to-key directory. A malicious service can compromise first contact or induce a trust reset. No media SFrame/insertable-stream E2EE is implemented. TURN can observe routing metadata, even when it cannot read DTLS-SRTP media. Rejected calls and disconnected sockets release media tracks. Device choices shown during a call apply to the next call.
